# YuE2 任务服务与 Claude plugin Skill 封装设计

**交付类型：源码核对与设计交付，非业务代码发布。**  
**版本：1.6｜日期：2026-09-18｜修正为云端签发上传地址、本地客户端主动上传。**
本次增加的是四个 Runner 能力的 MCP 对外封装；不增加执行后端或模型任务类型。详见 [10_Runner接口MCP封装与文件传输.md](10_Runner接口MCP封装与文件传输.md)。
本次修订只保留任务服务与 Claude plugin Skill 封装。原 Skill 的业务步骤和检查顺序保持，模型执行由本地脚本入口改为任务服务入口；移除应用实现、独立客户端和额外播放器设计。接口及模型绑定沿用 v1.2，未修改业务代码。
本文替代此前将翻唱、转录、编辑整体推迟的设计。四类业务能力及必要跨环境流程均纳入；普通生成是第一个验证场景，不是能力上限。本文所称“拟新增”“拟修改”均未部署；源码事实按固定提交引用。运行验证状态见《03_验证计划与实际检查》。

## 1. 结论摘要

### 1.1 推荐方案

复用 agent-sandbox 的 `/runner/submit`、`/runner/result`、`/runner/result_source`、内存队列、Task/Runner 和进度钩子。拟增加 **两个独立模型 Task（`yue2_task`、`sheetsage2_task`）、各自绑定的 Processor 与 environment，以及一个轻量服务型 Skill**。翻唱、编辑以现有任务及文件交接组合，不各建一套模型执行器。需要乐谱审阅或修改的节点返回文件后释放任务执行资源，下一次以新阶段任务继续。[S01][S05][S06][S17]

单台 AutoDL 上沿用现有 API + 本机 `web_runner` 子进程部署，不增加调度平台；在同一 API 侧增加 MCP 工具入口，复用四个 Runner 业务能力。`runner_upload` 只签发一次性、短效上传能力，实际字节由本地客户端 PUT 到同一监听器，再进入共享上传函数。模型进程分别使用 `/root/yue-env/bin/python`、拟议的 `/root/sheetsage2-env/bin/python`；权重与缓存位于 `/root/checkpoint`。原 Skill 的模型执行脚本保留在服务器端，Claude plugin Skill 只通过任务服务执行模型。[S13][S18]


### 1.2 必要修改与限制

必要修改集中在：模型请求适配；environment 到子进程的实际传递；任务独立目录；真实错误/退出码解释；通用输入上传；现有结果接口的资源清单、鉴权和下载修正；音乐任务小型文件记录；请求去重与恢复；Claude plugin Skill 的调用入口映射。现有上传会删除用户评测目录，不能直接用作音乐输入。现有下载没有音乐清单白名单和相应主体校验，不能原样向公网开放。[S05][S14]

以下项目不是已完成实测：AutoDL GPU、模型文件、两套 Python 环境、任务服务改造、插件封装后的真实任务调用与跨用户权限测试。用户工作区的 HEAD 和未提交修改也未取得；本次未执行仓库写入、分支切换、模型安装或业务代码修改；文档同步单独记录。

## 3. 本期范围与模型职责

### 3.1 权重、阶段与业务任务

| 模型 | 职责 | 环境与服务边界 |
|---|---|---|
| YuE2-3B | 风格/歌词→可选符号乐谱→语义 token→声学 latent | /root/yue-env → yue2_processor → yue2_task；处理生成、规划、再生成 |
| YuE2-Vae | 默认试听解码：latent→立体声音频 | 同一 YuE Pipeline 加载；不单建 Task |
| YuE2-Vae-legacy | 对同一 latent 的基准评测解码 | 非默认试听；仅在明确请求评测对比且部署了权重时选用，不能从 legacy 名称猜用途 |
| SheetSage2 | 音频→旋律、和弦、节拍、调性、结构、ABC、MIDI | /root/sheetsage2-env → sheetsage2_processor → sheetsage2_task；仅转录 |
| MERT-v2-FullSong | SheetSage2 自动加载的精确父模型；也可独立提取连续特征 | 作为 SheetSage2 依赖时不另建业务 Task，不替换为任意 revision |
| MERT-v2-30s | 短音频连续特征分析 | 非生成/翻唱/编辑必需；独立分析任务有明确需求再接入 |

以上职责来自官方配套资料，普通生成不增加独立 MERT 调用。连续 MERT 特征不是 YuE 的离散语义 token。[S18]

### 3.2 本期完整业务覆盖

| 用户意图 | 服务执行组合 | 检查步骤与限制 |
|---|---|---|
| 普通生成 | generate，cot=full/melody/off | full/melody输出可编辑ABC；off不输出可编辑乐谱 |
| 转录 | transcribe，task=full/melody-full/melody-vocal | 检查 warnings、ABC完整性、音乐准确性 |
| 录音翻唱 | transcribe→检查/必要时修改ABC→generate(cot=melody) | 旋律条件再生成；不承诺原歌手身份或波形 |
| ABC 翻唱 | inspect/必要时strip-chords→generate(cot=melody) | 不把有和弦ABC直接视为melody输入 |
| 编辑/改词/改编 | plan或已有完整结果→修改ABC/文本→inspect/compare→generate | 改动内容与保留约束分别记录；不称为局部音频修补 |
| 模式对比 | all_modes→逐模式保留结果及失败 | 只接受文本输入；不能把部分成功记为全部完成 |
| 原latent重解码 | decode，引用已验证的完整原生结果 | 不实现歌词或音乐内容编辑；不是断点续跑 |

已有功能依据原 Skill 与实际辅助脚本；服务接入工作是保留并连接这些能力，不是重新训练模型。[S17][S19][S25][S27]

不支持任意 MIDI 直接输入 YuE：上游这里接收的是文本与原生 ABC，SheetSage2 输入是音频；乐谱转换涉及节拍/调性等配套文件，不能把一个裸 MIDI 文件当成已经支持的输入。无 audio-reference、phonemes 或 local-inpainting 原生参数。[S17][S18]

### 3.3 流水线组织

服务入口按独立模型分开：`yue2_task` 只绑定 `yue2_processor`，允许 `generate|plan|all_modes|decode|score_check`；`sheetsage2_task` 只绑定 `sheetsage2_processor`，仅允许 `transcribe`。每个 Processor 使用自己的 environment，不再以一个跨模型 Task 根据 operation 切换处理器。`score_check` 的 inspect/strip_chords/compare 在 YuE Processor 的轻量分支执行 `abc_tools.py`，不加载 GPU 模型，不增加第三个通用命令执行 Processor。

翻唱与编辑由 Skill 串联这些阶段。自动步骤在上一个任务已结束、资源校验通过后继续；需要用户选择或修改乐谱时，先结束当前服务任务，保留 workflow_id、source_task_id、产物引用；完成原步骤的检查和修改后再继续。等待期间不占 GPU，不要求新建一个长期挂起的父 Runner。无需服务端动态 DAG、任意脚本或可视化编排器。

## 4. 系统职责、交互流程与接口契约

### 4.1 职责与部署

Claude plugin Skill 沿原步骤组织请求、调用 `runner_upload`、在本地执行返回的 `curl`、确认资产响应、检查、修改和取得产物；API 负责认证、上传能力签发与消费、校验、任务身份、队列及资源访问；YuE2Task / SheetSage2Task 各自负责模型参数校验、固定 Processor 绑定和状态结果组织；Processor 负责环境解析、具体 CLI、进程与输出；文件层负责任务隔离与产物发布。

服务、Worker 与模型执行进程同在一台 AutoDL，共享本机任务目录；Claude plugin Skill 通过配置的 HTTPS 任务服务入口调用。源码自身没有证明公网 TLS/认证已经具备，入口配置和凭据注入是部署验收项。[S05][S12][S13]

### 4.2 现有与拟新增接口

| 接口 | 来源 | 本方案动作 |
|---|---|---|
| `POST /runner/upload` | **前版已规划的通用上传接口** | 通用文件上传；multipart 的 file、user_id；返回 asset_id、sha256、size_bytes。按认证用户隔离，不绑定模型或 operation |
| `POST /runner/submit` | 已有 | 读取上传资产引用；校验所属用户、完整性与 Task 参数，使用现有队列 |
| `GET /runner/result?task_id=...` | 已有 | 查询真实任务状态和该任务已就绪的输出资源清单；每项包含 result_source_name |
| `GET /runner/result_source?task_id=...&result_source_name=...` | 已有 | 取清单中指定资源，修正 MIME/文件名并校验归属；不新增输出下载路由 |
| `GET /runner/task-internal` / `POST /runner/task-update-internal` | 已有、内部 | 继续用于 Worker 拉取和进度更新；不作为 Skill 的公开接口 |

删除原设计的音乐专用上传和公开重发布接口，不替换为其他业务专用别名。输出写入和结果登记属于 Task/Processor 收尾；客户端下载失败只重新查询同一 task_id 并重取同一 result_source_name。两个 GET 均为读取，不以查询触发推理、搬运、重发布或业务状态变更。

MCP 的 `runner_upload(file_path, client_os)` 不把文件内容放入 JSON，也不让服务器读取客户端路径。它签发同一监听器的 `PUT /api/uploads/{token}`，返回本地可执行命令；PUT 路由使用 owner-only 临时文件，并调用与 `POST /runner/upload` 共用的上传函数。返回 `asset_id`、`sha256`、`size_bytes` 才表示资产可提交。该 PUT 路由是传输适配，不是新的 Runner 业务接口。

取消的最小范围是 Runner/执行器超时、进程取消信号的正确回收。本版不新增公开取消接口；停止当前等待不自动取消已经接受的服务任务。

现有 TaskRunnerResponse.code 是 JSON 字段，不自动改变 HTTP 状态。新的上传及模型任务校验错误使用真实 4xx/5xx；客户端检查 HTTP 和 JSON code 两者。保留既有 code/msg/data 外壳与旧任务调用方式。[S05][S12][S15]

### 4.3 提交示例及元数据

完整可解析示例位于 `examples/`。最小生成请求：

```json
{
  "parameter": {"task_name": "yue2_task", "reset": false, "user_multi_task": false},
  "payload": {
    "code_input": {"userId": "user_demo", "workflow_id": "wf_demo"},
    "operation": "generate",
    "request": {
      "id": "rain_window",
      "style": "Mandarin piano pop, female voice, acoustic piano, 88 BPM",
      "lyrics": "[Verse]\n雨落在窗前\n[Chorus]\n把想念唱成诗篇",
      "cot": "full",
      "seed": 831001
    }
  }
}
```

`parameter/payload` 与 code/msg/data 沿用现有外壳；yue2_task、sheetsage2_task、operation、workflow_id、request、asset/source引用均为拟新增业务契约。客户端 `userId` 只为兼容既有用户索引结构，API 根据认证主体核对并重写，不能据此授权。客户端不允许 `_service`、解释器、模型目录、脚本、GPU或输出路径。

拟新增头 `Idempotency-Key` 由客户端首次提交前生成并保存。Music API 在可信命名空间内按“认证主体+请求键”生成固定任务标识（例如 UUID5），并独占创建任务记录；该 ID 不承担访问控制。不同请求键允许同样音乐参数再次生成；同键不同规范化请求返回409；同键同请求返回原 task_id。规范化摘要涵盖task_name、operation、参数、资源内容摘要与必要关联信息，不因JSON空白变化重新采样。

API在接受请求时写入内部 `payload._service={task_id, owner_id, request_digest, execution_profile_digest}`；通过原 Dict 序列化传给 Worker。YuE2Task.prepare 和 SheetSage2Task.prepare 均为纯校验/转换，读取此 ID，不再生成随机 ID、读取用户输入路径或复制文件。这样 API 和 Worker 两次 prepare 使用同一标识，无需修改所有旧 Task 的 prepare 签名。[S04][S05][S06]

### 4.4 状态与执行结果

复用 `info=pending`、进度字符串、`save_write`、终态 `end/error` 与 `finished`。新音乐进度名称 `dispatch_yue2_task` / `dispatch_sheetsage2_task` 只是现有 str 状态机制中的值；对外真实阶段放在 `result.stage`：preparing/executing/validating/ready，不生成百分比。`result` 扩展 `outcome`、`model_completed`、`delivery_status`、`artifacts`、`error`；它们描述结果，不构成另一套调度状态机。[S07][S15]

`model_completed=true` 只表示模型阶段完成并找到可验证输出；文件发布失败时可与 `delivery_status=failed` 并存。`end + outcome=needs_review` 表示文件可交付但截断或符号检查未通过，必须醒目提示，不将其等同音乐质量合格。

音乐 progress 上报完整结果快照，因为现有 post_task_update 会替换 result；两个模型 Task 复用音乐结果函数 `save_music_result` 按现有四路径内部约定组合清单，一次报告。不要把增强结果交给只发送四路径的基类保存方法后造成信息丢失。公共 serializer 从快照中剔除本地绝对路径与凭据，只输出资源键和相对下载地址。[S05][S07]

## 5. 参数处理、environment 配置和模型目录迁移

### 5.1 已核实的原生请求与优先级

| 字段 | 原生类型/约束 | 默认与服务规则 |
|---|---|---|
| style | str，必须提供 | 源码允许空串；Skill应指出需求过少，不能伪称原生禁止空串 |
| tags | helper别名 | 转换为style；两者不相等报错；服务只公开规范化style |
| lyrics | str，必须提供 | 可为空串；无需伪造不存在的 instrumental 参数 |
| cot | full / melody / off | 默认full；CLI --cot 覆盖请求cot |
| seed | 严格整数，`0 <= seed < 2**63` | 默认831001；bool不作为整数；原样记录 |
| id | `[A-Za-z0-9][A-Za-z0-9_.-]{0,179}` | 默认song；只作原生请求标识，不作任务目录 |
| abc | 非空str或null | off禁止ABC；melody需无和弦符号 |
| abc_path | helper接受的文件引用 | 相对请求文件所在目录；服务不对外开放路径，改用abc_source |
| cfg_scale | null或有限数值[0,20] | null时off使用1.01，full/melody使用1.0 |

helper 白名单只有 `style,tags,lyrics,cot,seed,abc,abc_path,cfg_scale,id`，未知字段报错。`abc`、`abc_path`、`--abc-file` 三个非空来源互斥，不存在“哪个覆盖哪个”；`--abc-file` 相对进程cwd，而`abc_path`相对请求文件父目录。服务只传一个规范化请求与至多一个由资源解析得出的绝对ABC路径，不再用CLI重复覆盖cot。[S19][S20]

helper 没有 `--seed`、`--duration`、`--output-format` 或任意采样字段透传；虽然底层 runtime 有 Sampling/GenerationConfig，不代表当前辅助CLI提供这些选项。节奏、语言、乐器写进style不能宣称为强制可控的原生数值字段。[S19][S20]

### 5.2 服务端文件与argv映射

请求JSON来自原 Skill 的请求组织步骤或用户提供的原生JSON。Skill读取请求文件→解析并规范化→POST中的request对象；服务器保存 `input/request.original.json` 和 `input/request.execution.json`。无需为了普通文本生成新增“请求JSON上传阶段”。原 `assets/prompt.json` 仅是 Skill 目录内模板，不能在AutoDL任务间共用写入。[S17][S24]

受控模型执行数组示例（部署路径是拟议值，参数名已由源码确认）：

```text
[
 "/root/yue-env/bin/python", "-u",
 "/root/apps/YuE/skills/yue2-music/scripts/run_yue2.py", "generate",
 "--request", "/root/agent-sandbox-data/tasks/<task_id>/input/request.execution.json",
 "--output", "/root/agent-sandbox-data/tasks/<task_id>/work/native",
 "--model", "/root/checkpoint/YuE2-3B",
 "--vae", "/root/checkpoint/YuE2-Vae",
 "--offline", "--device", "cuda", "--memory-budget-gib", "24"
]
```

`cwd=/root/apps/YuE/skills/yue2-music` 单独设置，所有关键路径传绝对值，不使用shell拼接。`--output`是**新目录**；`common.fresh_directory`使用`exist_ok=False`。Processor可以创建task/input/work，但不得提前创建work/native。重复调用也不能让helper覆盖已有采样目录。[S19][S26]

转录数组将操作固定映射为 `scripts/transcribe.py <绝对音频路径> --output <新目录> --task melody-full --model /root/checkpoint/SheetSage2 --base-model /root/checkpoint/MERT-v2-FullSong --offline --device cuda --dtype bf16 --threads 4`，解释器改为SheetSage2环境。`max_seconds`默认不传；明确请求裁切才传，并记录裁切，不用它掩盖资源不足。[S25]

其他操作固定映射：`all_modes→all-modes`；plan、decode分别对应同名子命令；decode的`--source`只指向已授权且原生manifest验证通过的完整结果目录。score_check映射inspect/strip-chords/compare，input/output/voices白名单化，不接受自定义模块或命令。[S19][S27]

`examples/sandbox.music.example.yaml` 是与已读列表结构一致的完整拟议AutoDL部署样例，保留 `preprocess → 具体_processor → environment`，没有顶层 `_processor` 注册表。核心增量：

完整配置还包括两个模型路径、任务绑定和原bootstrap。该样例不是已经生效配置；新增bootstrap.music也必须修改实际from_config，不能只写YAML。[S01][S02][S12]

具体传递路径：OmegaConf.load→load_preprocess(cfg)→注册类.from_config(cfg)→构造函数保存environment→共享轻量`resolve_python_environment`→`<environment>/bin/python`→create_subprocess_exec/anyio.open_process参数数组。BaseProcessor不统一改变执行模式；旧处理器未配置environment时保持原行为。先在两个新Processor实现，旧子进程Processor日后选择接入时按实际调用链逐个验证。[S08][S09][S38]

预检查使用目标解释器读取sys.executable/sys.prefix及包版本，并分别检查cwd、脚本、权重、ffmpeg、CUDA BF16条件。YuE侧需要的版本为torch2.10.0、transformers4.57.6、numpy2.2.6；SheetSage2资料列出torch2.8.0、transformers4.45.2、numpy1.24.3。不能将两套依赖装进/root/yue-env。[S18][S23]

环境目录或解释器错误立即失败，不回退到`python`或sys.executable。sys.executable可能经符号链接指向基础二进制，因此同时核对sys.prefix；不误拒绝正常venv符号链接。将目标bin放入子进程PATH，设置受控VIRTUAL_ENV、PYTHONNOUSERSITE、PYTHONUNBUFFERED；清除宿主PYTHONHOME/PYTHONPATH污染。GPU、缓存等只从服务端配置注入，不把完整环境或密钥打进日志。

### 5.3.1 模型、环境、preprocess 与 Task 的固定绑定（v1.1 修订）

每个独立执行模型分别注册 Task 和 Processor，并通过该 Processor 的 environment 选择解释器。`/root/yue-env` 只属于 YuE2 运行链，不是所有音乐模型的公共环境。以下 Task/Processor 注册名和附加目录均为拟新增设计，未部署。

| 独立执行模型 | environment | preprocess 注册名 | Task 注册名 | 允许的 operation |
|---|---|---|---|---|
| YuE2 生成运行链 | `/root/yue-env` | `yue2_processor` | `yue2_task` | generate / plan / all_modes / decode / score_check |
| SheetSage2 转录 | `/root/sheetsage2-env`（拟建） | `sheetsage2_processor` | `sheetsage2_task` | transcribe |
| MERT 独立特征分析（有该业务时启用） | `/root/mert2-env`（预留，未安装） | `mert2_processor`（预留） | `mert2_task`（预留） | 接入独立分析时再固定；本版不注册 |

Task.from_config 只允许绑定本模型的 Processor，缺少绑定或类型不符即报错；客户端的 operation 只能选择该 Task 内已列出的动作，不能用它跨模型选择解释器。API 校验 `task_name + operation` 的合法组合，不接受客户端指定 environment、processor、脚本或模型路径。规范化请求摘要包含 task_name，服务端 execution_profile_digest 包含 Task/Processor/环境/脚本/权重绑定；两个任务可复用请求归属、日志和结果函数，不能重新合并为一个跨模型分发 Task。

YuE2-Vae 是 YuE2 Pipeline 内加载的权重组件；MERT-v2-FullSong 作为 SheetSage2 父模型时由其内部加载。这些内部依赖不冒充独立环境切换。需要将组件作为独立执行服务时，再新增其实际可运行的环境、Processor、Task 和文件交接契约，不通过修改配置名称假称已经拆分进程。[S18][S21][S25]

跨模型业务按阶段调用：`sheetsage2_task(transcribe)` → ABC 产物/审阅 → `yue2_task(score_check)` → `yue2_task(generate)`。编辑使用已有谱或先取得乐谱 → 修改乐谱 → `yue2_task(score_check)` → `yue2_task(generate)`。阶段共享 workflow_id，通过 asset_id 或 task_id/result_source_name 传递文件，不共享 Python 依赖或模型对象。

## 6. 文件同步、产物交付和异常处理

### 6.1 通用输入上传、用户隔离与任务目录

唯一新增上传路径为 **POST /runner/upload**，采用 multipart/form-data：`file` 为单个文件，`user_id` 为资源所属用户。通用接口不接收 task_name、operation、environment 或客户端服务器路径；不调用模型、不安装依赖、不默认解压归档。文件大小和配额由通用上传配置控制，音频解码及 ABC 语法合法性由引用它的 Task/Processor 检查。

参考 `extract_standard_file` 的用户隔离思路，**不复制其清空用户目录、解压评测 ZIP 的业务行为**。请求中的 user_id 必须与认证主体对应；资源目录使用服务器规范化的用户标识，不直接拼接未经校验的字符串。[S14]

拟议布局：

```text
/root/agent-sandbox-data/
  uploads/<canonical_user_id>/<asset_id>/
    source.<ext>             服务端命名；原始文件名保存在记录中
    asset.json               user_id、asset_id、sha256、size_bytes、相对路径
  tasks/<service_task_id>/
    task.json                API维护请求、主体、真实状态与已绑定输入
    input/                   原始/执行请求及任务使用的输入文件
    work/native/             由上游helper创建的新输出目录
    artifacts/               已校验完成的文件
    logs/stdout.log
    logs/stderr.log
    result-manifest.json     内部输出清单及完成记录
```

每次上传分配一个新的 asset_id，不覆盖同名文件、不删除该用户其他上传。写入临时位置时计算实际 sha256 和 size_bytes，完成写入并原子登记后才返回成功；中断上传不产生可引用资产。模型权重不参与此接口的普通任务输入同步。

返回 code/msg/data 外壳，data 中含 `asset_id`、`sha256`、`size_bytes`。提交阶段引用 asset_id：转录使用 `payload.audio_asset_id`；用户修改后的 ABC 使用 `payload.abc_source.asset_id`。sha256/size_bytes 供调用方核对，服务器始终以资产登记及实际文件校验为准，不把客户端回传的摘要当作授权或完整性证明。无需为传回摘要再增加重复的模型参数。

`/runner/submit` 接受前检查资产已完成、归属匹配、记录存在、大小与摘要一致，并将输入引用绑定到该服务任务；Task.prepare 保持纯转换，不在 API/Worker 两次 prepare 中重复复制文件。dispatch 准备阶段再通过共用资源解析函数取得受控路径，按需将小型输入复制到任务 input/；已绑定运行任务的输入不能被清理。任一输入失败在启动模型前报告。

已有输出作为后续任务输入时使用 `{task_id, result_source_name}`，服务内部按同一用户权限解析，无需下载再上传；按原步骤修改过的文件作为新输入上传。普通文本 request 可以直接进入 submit JSON，无需额外上传一次。绝对路径、`..`、NUL、符号链接逃逸及跨用户引用均拒绝。

### 6.2 产物清单与原生结果

普通生成原生audio.flac及request/config/result、plan/tokens/latent保留在服务器；外发默认音频、请求、结果摘要、存在时的ABC。latent/token不是任务状态内嵌数据，也不随每次下载自动发送。转录只列实际存在的score.abc、MIDI及报告，不把某个可选文件名写死成必有。[S21][S25]

先执行原生verify_result或转录manifest/ABC检查，再检查helper的run.json、abc_check、退出码。然后由轻量清单记录result_source_name、相对路径、bytes、SHA256、MIME、音频属性、请求摘要、模型和代码版本、解释器。发布是同文件系统原子rename或资源层已有提交操作；API仅暴露ready记录，不提供还在写入的文件。[S19][S21][S22][S25]

完整结果目录和可交付清单不应重复复制所有latent。优先将已核验目录原子移到artifacts/native，再对其中文件登记与 result_source_name 对应的路径；移动后内部相对manifest仍可验证。若原生输出包含绝对路径元数据，只作为来源记录不再用于资源寻址。请求和随机种子随任务归档，密钥不入档。

#### 输出寻址约定

`GET /runner/result` 的 `data.result.artifacts` 为拟扩展的清单字段；每个已就绪条目包含 result_source_name、filename、media_type、size_bytes、sha256。清单项必须逐一对应内部 `result[result_source_name]` 的已登记文件路径，以兼容现有 result_source 寻址方式。内部路径继续存在，公共 JSON 不返回服务器绝对路径；旧任务的 result_path、log_run_path 等已有键仍可沿用，不强制改名。

客户端只从实际清单选取名称，用既有查询参数 `task_id + result_source_name` 获取文件。无需额外 artifact_id、输出 asset_id、资源清单端点或下载URL分配端点。可选文件未产生就不列出，metadata 字段不能被当作文件名访问。读取端按清单白名单与所属用户检查；未就绪、缺失、过期或无权限分别返回错误，禁止把 JSON 错误体保存成音频。大小及摘要是示例元数据时必须标注，真实响应只能填真实值。

### 6.3 必须正确解释退出码

| 执行类型 | 判断 |
|---|---|
| generate | exit0且run.results.complete、原生校验通过→正常交付 |
| generate/plan | exit1可能是needs_review，不一定模型异常；按truncated与abc_check解释，交付时加警告并阻断自动进入要求乐谱合格的下一阶段 |
| all_modes | 每个模式单独记录；部分失败→outcome=partial、info=error，保留成功文件，不声称全部成功 |
| decode | 验证source完整原生结果和主模型identity；退出1可能继承截断标记，不能称断点恢复 |
| transcribe | 缺ABC或abc_error即失败；已有LAB/MIDI不等于翻唱前置成功 |
| score_check compare | exit1表示不满足所检查的不变量；它是检查结果，不等于工具崩溃；有意修改节奏时记录允许差异，不伪造旋律未变 |
| exit2 / 进程异常 | 解析失败、环境错误或执行异常，依据stderr/failure.json分类 |

这些分支直接来自辅助脚本，单独读取result.json里的complete会漏掉需复核情况。[S19][S25][S27]

### 6.4 文件完成、读取重试与恢复

Task/Processor 负责完成文件写入、原生校验和结果登记；这些步骤成功后，已就绪清单随原进度机制写入任务结果，调用方通过现有两个 GET 读取。`delivery_status=ready` 表示文件和寻址记录已就绪，不表示客户端已经下载成功；无需客户端确认下载接口。

模型已完成而文件落盘/登记失败：保留已有原生结果及诊断，记录 `model_completed=true, delivery_status=failed`，按既有 error 结束。可在服务端原有收尾/维护流程中有限重试登记；未恢复时向用户明确报告。**不提供公开重发布接口，也不把恢复操作藏进 GET。** 真正丢失或损坏的音频无法靠再次读取恢复，修复前不能列为可下载；重新采样需要新的明确请求。

客户端下载失败：重新 GET /runner/result 读取同一任务的现有清单，再按同一个 result_source_name GET /runner/result_source；已确认名称和摘要未变时可以直接重试后者。下载先写 .part，校验后再 rename，最多3次（客户端策略值）。读取失败不得重新 POST /runner/submit，也不得改变 seed、歌词或采样参数。无权限不自动重试，临时网络错误才进入有限重试。

现有任务只在内存保留并按TTL删除。为防止音频尚在磁盘而查询不可恢复，拟增音乐任务专用小型文件记录，复用现有维护循环，不引入数据库/队列平台。API是task.json唯一写入者；Worker写结果manifest，进度经现有内部接口更新。API收到终态丢失时可从已完成manifest校正，不凭音频文件存在猜成功。API重启后已排队音乐任务可按既有队列重建；曾经执行中的任务标记interrupted，检查结果/子进程后人工决定，不自动重新采样。[S11][S13]

task创建与Idempotency-Key占位要使用独占创建及原子JSON写入；记录完整落盘后再入队/返回成功。重复看到初始化中的目录返回可重试的409，不另分配采样任务；崩溃遗留空记录在启动检查中处理。此处只解决当前任务交付与去重，不宣称exactly-once推理或模型续跑。

清理按样例7日保留期（可配置）处理已结束任务及无人引用的输入，保留故障诊断宽限期；不删运行中、发布中和下载持有句柄的对象。与清理竞争时用临时占用标记/受控文件句柄，并通过测试确认。需长期保留的音频下载并保存，不把会过期的服务资源地址当作永久文件。

### 6.5 权限边界

当前公共runner路由没有这里需要的用户认证；内部nonce仅用于Worker。音乐部署的外部submit必须在入口强制task_name属于{yue2_task, sheetsage2_task}白名单，并校验各自operation，不能通过改成ResearchAgent或旧评测task绕过音乐认证与执行限制。拟在音乐部署配置一份服务端管理的“令牌摘要→用户主体”映射，0600权限，调用凭据由服务配置安全提供，并与对应用户绑定，不放在提示词、请求产物或argv。单用户试用可只有一条映射；多用户必须逐用户分配，不能所有用户共享无归属的key。部署后的密钥发放/轮换属于待验收配置，不声称已连接秘密管理系统。[S05][S12]

通用 upload、submit、result、result_source 均核对同一主体；上传路由不依赖两个音乐 Task 的枚举，具体任务的业务入口继续各自验证。code_input.userId只能与主体一致。内部nonce端点禁止公网直接访问，管理日志和旧评测接口不对不可信音乐客户端开放；生产入口认证默认开启。旧非音乐部署若保持兼容，仍须明确其原有安全限制，不能凭项目名称“sandbox”认定为安全执行隔离。

### 6.6 生命周期、超时与GPU并发

stderr/stdout并行消费、限长摘要、完整受控日志、退出码入结果。超时用总deadline，不继承旧60秒静默终止。子进程单独会话/进程组，取消或超时先TERM，宽限期后KILL，await回收，确认后才报告finished释放任务槽。测试还需检查上游有无脱离进程组的后代。[S09]

本期AutoDL使用一个API实例、一个受管Worker、`max_ongoing_tasks=1`；控制点是唯一API维护的ongoing队列，而非某个Processor局部锁。Worker现有semaphore100不等于GPU并发100；本配置从取任务入口限制到1。代价是该实例CPU任务也顺序执行，先接受这一明确代价，不建立资源调度器。[S05][S06][S11]

此限制不覆盖其他API实例或用户手工启动的GPU进程；部署验收禁止同GPU另开绕过入口的执行服务。Worker意外死亡时，音乐模式不要沿旧逻辑立即重新派任务：当前任务标记错误、停止取新任务，清理残存模型进程并确认资源释放后恢复服务。SIGKILL场景不能靠Python finally承诺全部清理；本期采用失败后暂停调度与运维恢复，不承诺无人值守自愈。[S13]

`web_client_timeout`原实现依据requested_at清除尚未开始的任务，result查询并不刷新该字段。音乐部署设为-1，接受的任务不因调用连接断开消失；容量和排队超时若要增加，应使用显式队列策略，而非借用“客户端断开”语义。[S05][S13]

## 9. 文件级实施清单、依赖顺序与验证计划

完整文件级表见《02_文件级实施清单》，逐项列出已有/拟新增、类函数、必要性、兼容影响和测试编号。完整可执行命令与通过标准见《03_验证计划与实际检查》。

执行顺序：固定包含PR11的工作基线→agent-sandbox的音乐参数/Task/Processor与必要资源扩展→无GPU配置/生命周期/文件/协议回归→AutoDL两个环境及真实采样/转录/翻唱/编辑→按已验证契约封装Claude plugin Skill→验证原业务步骤与结果获取。禁止先把一个不可工作的插件包发给用户再假称集成完成。

最低测试覆盖：真实解释器来源；旧任务兼容；原生字段/CLI互斥；fresh output目录；非法路径与跨用户资源；double prepare同ID；真实HTTP状态；stdout/stderr和进程组；单GPU并发；文件登记恢复/下载重试不重采样；API重启后的结果读取；官方脚本exit1/2解释；SheetSage2无ABC拒绝后续生成；Skill原步骤保持、有限查询和结果取得。

模拟执行不证明模型可用；短样本不证明完整目标场景；可播放文件不证明旋律保留、歌词准确或翻唱质量。[S17][S19][S25]

## 10. 目标符合性矩阵、过度设计审查与待验证事项

完整12项目标映射与删减表见《04_符合性审查与决策》。本文设计覆盖本轮四项交付，代码实施与运行验收仍未完成。当前可核实的是固定源码基线、现有调用链、原生参数和Skill入口映射；未核实的是用户/AutoDL实际工作区、已安装环境、权重revision、外网服务入口/令牌部署和真实运行结果。

本版增加必要的 Runner MCP 协议封装；不做独立调度平台、按权重数量创建Processor、通用DAG、插件市场、独立会话系统、自动模型依赖安装。MERT独立分析和legacy评测由具体分析/评测请求触发，不加入普通生成的必经链路。翻唱、转录、编辑及文件流水线留在本期设计，不能再作为“过度设计”删掉。

设计关键限制需由实施验收解除：官方SheetSage2模型快照及父模型匹配；目标GPU BF16/显存；服务凭据与公网入口；音乐任务记录恢复；实际部署的服务与插件契约版本是否一致。任一缺失都应明确报错，不能静默换环境、换模型、缩短歌曲或重新采样。
