# v1.1：按独立执行模型绑定环境、preprocess 与 Task

本文件记录2026-09-17用户纠正后的设计变更，不表示已创建AutoDL目录或修改业务代码。

## 1. 模型、环境、preprocess 与 Task 的固定绑定（v1.1 修订）

每个独立执行模型分别注册 Task 和 Processor，并通过该 Processor 的 environment 选择解释器。`/root/yue-env` 只属于 YuE2 运行链，不是所有音乐模型的公共环境。以下 Task/Processor 注册名和附加目录均为拟新增设计，未部署。

| 独立执行模型 | environment | preprocess 注册名 | Task 注册名 | 允许的 operation |
|---|---|---|---|---|
| YuE2 生成运行链 | `/root/yue-env` | `yue2_processor` | `yue2_task` | generate / plan / all_modes / decode / score_check |
| SheetSage2 转录 | `/root/sheetsage2-env`（拟建） | `sheetsage2_processor` | `sheetsage2_task` | transcribe |
| MERT 独立特征分析（有该业务时启用） | `/root/mert2-env`（预留，未安装） | `mert2_processor`（预留） | `mert2_task`（预留） | 接入独立分析时再固定；本版不注册 |

Task.from_config 只允许绑定本模型的 Processor，缺少绑定或类型不符即报错；客户端的 operation 只能选择该 Task 内已列出的动作，不能用它跨模型选择解释器。API 校验 `task_name + operation` 的合法组合，不接受客户端指定 environment、processor、脚本或模型路径。规范化请求摘要包含 task_name，服务端 execution_profile_digest 包含 Task/Processor/环境/脚本/权重绑定；两个任务可复用请求归属、日志和结果函数，不能重新合并为一个跨模型分发 Task。

YuE2-Vae 是 YuE2 Pipeline 内加载的权重组件；MERT-v2-FullSong 作为 SheetSage2 父模型时由其内部加载。这些内部依赖不冒充独立环境切换。需要将组件作为独立执行服务时，再新增其实际可运行的环境、Processor、Task 和文件交接契约，不通过修改配置名称假称已经拆分进程。[S18][S21][S25]

跨模型业务按阶段调用：`sheetsage2_task(transcribe)` → ABC 产物/审阅 → `yue2_task(score_check)` → `yue2_task(generate)`。编辑使用已有谱或先取得乐谱 → 乐谱修改 → `yue2_task(score_check)` → `yue2_task(generate)`。阶段共享 workflow_id，通过 asset_id 或 task_id/result_source_name 传递文件，不共享 Python 依赖或模型对象。


## 2. 验收差异

V02验证两个Task分别注册且仅绑定本模型Processor；V03验证task_name/operation允许组合；V06从两条真实调用链返回sys.executable/sys.prefix，交叉绑定报错且坏环境不回退。共享Runner、任务队列、结果函数和文件协议不改变模型入口各自独立的规则。

## 3. 版本边界

v1.0中单一music_task设计已被替换。现有服务代码未修改，本版两个Task与对应注册仍为拟新增。MERT独立分析未注册，其环境仅作为将来接入时必须同样分离的示例。YuE2-Vae、MERT父模型的内部加载保持上游实现；另立独立执行契约时才能声称这些组件也有独立运行环境。
